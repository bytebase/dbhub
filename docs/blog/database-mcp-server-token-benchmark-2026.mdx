---
title: "Database MCP Server Token Benchmark: DBHub vs MCP Toolbox vs Supabase MCP"
description: "We measured how many tokens three database MCP servers add to a Claude Code session. DBHub uses 468, MCP Toolbox uses 7,674, and Supabase MCP uses about 11,600."
---

*November 17, 2026*

Every MCP server puts its tool definitions into the agent's context window. The larger they are, the less room is left for your schema, your query results, and your code. Keeping them small is what DBHub is built for.

We first measured this in [December 2025](/blog/postgres-mcp-server-review-dbhub#token-efficiency). This post repeats the benchmark with current versions.

## Results

We added each server to Claude Code in its default configuration and read the token count of its tool definitions from the `/context` command.

| MCP Server | Tools | Tokens | Compared with DBHub |
|------------|-------|--------|---------------------|
| **DBHub** 1.7.0 | 2 | **468** | |
| MCP Toolbox 1.17.0 | 29 | 7,674 | 16 times more |
| Supabase MCP 0.17.0 | 36 | 11,600 | 25 times more |

We chose these two because they are the servers DBHub is most often compared with. [MCP Toolbox](https://github.com/googleapis/genai-toolbox) is the other popular multi-database server, and [Supabase MCP](https://github.com/supabase-community/supabase-mcp) is the most popular vendor-specific one.

## Why DBHub uses fewer tokens

DBHub's tool definitions are not shorter than the others. An average tool costs about the same in all three servers:

| MCP Server | Tokens per tool |
|------------|-----------------|
| DBHub | 234 |
| MCP Toolbox | 265 |
| Supabase MCP | 322 |

DBHub uses fewer tokens because it has fewer tools. It has two:

- `execute_sql` runs SQL statements.
- `search_objects` finds schemas, tables, columns, indexes, and procedures. It uses [progressive disclosure](https://www.anthropic.com/engineering/code-execution-with-mcp#progressive-disclosure): you pass a name pattern and a detail level, so one tool covers every object type.

The other two servers use one tool per task. MCP Toolbox has a tool for each object type, such as `list_tables`, `list_views`, `list_indexes`, and `list_triggers`, plus tools for database administration. Supabase MCP covers the whole Supabase platform, including projects, branches, edge functions, and notebooks. Its `create_notebook` tool alone uses 1,700 tokens, more than three times DBHub's total.

Both servers do more than DBHub, and both let you disable tools. The numbers above are for the default configuration.

## Why all three numbers are lower than last year

| MCP Server | December 2025 | November 2026 |
|------------|---------------|---------------|
| DBHub | 1,400 | 468 |
| MCP Toolbox | 19,000 | 7,674 |
| Supabase MCP | 19,300 | 11,600 |

DBHub itself barely changed. Its two tool definitions went from 1,664 characters to 1,468, which is 12% shorter, while the reported token count fell by two thirds. Most of the drop comes from two changes in Claude Code.

The first is token accounting. In December 2025, `/context` reported 607 tokens for an `execute_sql` definition that was 496 characters long. A definition cannot use more tokens than it has characters, so that figure included per-tool overhead. Today the same tool is reported at 119 tokens. MCP Toolbox dropped by a similar amount, about 400 tokens per tool.

The second is [MCP tool search](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search), which is now enabled by default. Claude Code defers tool definitions and loads only tool names and server instructions at session start. A definition enters the context window when the agent searches for the tool and uses it.

Tool search helps every server, but definition size still matters. The definitions are loaded once the agent starts working with the database: 468 tokens for all of DBHub, and thousands for the other two if the agent loads all of their tools. With `ENABLE_TOOL_SEARCH=false`, or in an MCP client without tool search, every definition is loaded upfront.

DBHub's lead has also grown. In December 2025, MCP Toolbox and Supabase MCP each used about 14 times as many tokens as DBHub. Today they use 16 and 25 times as many.

## How to reproduce

We used Claude Code 2.1.326. These commands add the three servers and print the context report:

```bash
claude mcp add dbhub -- npx -y @bytebase/dbhub@1.7.0 --transport stdio --demo

claude mcp add toolbox \
  -e POSTGRES_HOST=127.0.0.1 -e POSTGRES_PORT=5432 -e POSTGRES_DATABASE=postgres \
  -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres \
  -- npx -y @toolbox-sdk/server@1.17.0 --prebuilt postgres --stdio

claude mcp add supabase -- npx -y @supabase/mcp-server-supabase@0.17.0 --access-token <token>

claude -p "/context"
```

MCP Toolbox connects to PostgreSQL at startup, so it needs a reachable database. For Supabase MCP we used the local npm server, not the hosted one.

To try DBHub, see the [installation guide](/installation).
